Module 1
Data-Level Parallelism & Flynn's Taxonomy

Flynn's Taxonomy (1966)

Classify machines by how many instruction streams and data streams run concurrently.

SIMDSingle Instruction, Multiple Data — one instruction stream drives the same operation across many data elements at once.

SISD a classic uniprocessor. MIMD independent cores (threads, MPI ranks). MISD is rare. Today's CPUs blend all of these.

SIMD = one op, many data.

Scalar vs. Vector Execution

Scalar — one result per op
SIMD — one op, many results
Same silicon, more throughputA single packed add operates on a whole vector of lanes — no extra instruction fetch, no extra threads. This is parallelism inside one core.

Where DLP Lives: the Inner Loop

SIMD wants adjacent values in memory that can be processed independently — exactly the body of a tight loop over an array.

An ideal vector loop

for (int i = 0; i < n; i++)
    c[i] = a[i] + b[i];   // lanes independent

Each iteration is independent, contiguous, and does the same work — the compiler can fold 4, 8, or 16 iterations into one vector instruction.

Vector widthA 256-bit register holds 8 float or 4 double; the loop advances by that many per step.
Breaks DLPcross-iteration dependences (a[i]=a[i-1]+…), data-dependent branches, function calls, and pointer aliasing.

SIMD Hardware — Registers, Widths & Lanes

The Intel SIMD Lineage

ExtensionYearRegisterWidthfloat lanesdouble lanes
MMX1997MM0–7 (reused FP)64-bitinteger only—
SSE / SSE2…41999XMM0–15128-bit42
AVX / AVX22011YMM0–15256-bit84
AVX-5122016ZMM0–31512-bit168
The patternEach generation doubles the register width (and adds registers). Wider register = more lanes per instruction = more work per cycle. AVX-512 also adds dedicated mask registers (k0–k7).

Registers, Lanes & Widths

A "lane" = one element slot in the register.
Lane countlanes = register_bits / (8 × sizeof(T))

256-bit YMM ÷ 32-bit float = 8 lanes. ÷ 64-bit double = 4 lanes. Narrower elements ⇒ more lanes ⇒ more parallelism (e.g. 32 × int8 in a 256-bit register).

Note: in Intel terminology a "word" is 16 bits; single-precision FP is a doubleword (32b), double-precision is a quadword (64b).

Packed vs. Scalar; Operand Naming

Packed (P)Operate on all lanes of the register at once — the SIMD case.
Scalar (S)Operate on only the lowest lane; the rest pass through unchanged.

So addps adds 4 packed floats; addss adds one float in lane 0.

SuffixMeaning
PSPacked Single — 4 (or 8/16) × 32-bit FP
PDPacked Double — 2 (or 4/8) × 64-bit FP
SSScalar Single — one 32-bit FP, lane 0
SDScalar Double — one 64-bit FP, lane 0
A / UAligned / Unaligned memory operand

e.g. movaps = move aligned packed single; movups = unaligned.

FMA & Why Width Isn't Everything

Fused Multiply-Addx = y + c*z as a single instruction, at the same throughput as a lone + or * — and with one rounding step.

So common in dot products, matrix multiply, and stencils that hardware does multiply-and-add together. A packed FMA on a 256-bit register does 8 multiply-adds per instruction.

The catchPeak vector throughput assumes data streams in from cache at full rate. Memory bandwidth, alignment, and dependences usually decide real speedup — not the register width on the spec sheet.

Doubling lanes only helps if you can feed them.

Module 3
Using SIMD — Auto-Vectorization & omp simd

The Ladder of Effort

1 · Auto-vectorizeJust turn on optimization. Compiler finds & vectorizes clean loops. Try this first.
2 · Guide itAdd #pragma omp simd, restrict, alignment hints when the compiler is too cautious.
3 · IntrinsicsHand-write the vector ops when you need full control (Module 4).
In theory the compiler understands all of this It schedules instructions, uses FMAs, and packs SIMD lanes. In practice it often needs your help — different flags, a code rewrite, or an explicit pragma to prove the loop is safe.

Auto-Vectorization & Compiler Reports

Enable & target the ISA

# GCC / Clang
gcc -O3 -march=native -ffast-math saxpy.c
gcc -O3 -mavx2 -mfma   saxpy.c

# vectorization report
gcc  -fopt-info-vec-optimized saxpy.c
gcc  -fopt-info-vec-missed    saxpy.c
clang -Rpass=loop-vectorize -Rpass-missed=loop-vectorize saxpy.c

-O3 turns on the vectorizer; -march=native lets it use the widest ISA your CPU supports.

Read the report"loop vectorized" ✓ vs. "not vectorized: data dependence" / "unknown alignment" / "possible aliasing" — the message tells you what to fix.
-ffast-mathLets the compiler reassociate FP (needed to vectorize reductions) — but changes results in the last bits. Use deliberately.

#pragma omp simd

A promise to the compiler"This loop is safe to vectorize — ignore your conservative dependence/aliasing analysis." Part of OpenMP, portable across compilers.

#pragma omp simd
for (int i = 0; i < n; i++)
    c[i] = a[i] + b[i];

// vectorized reduction
#pragma omp simd reduction(+:sum)
for (int i = 0; i < n; i++)
    sum += x[i] * y[i];
No safety netThe compiler will not check correctness. If iterations really do depend on each other, omp simd produces a fast wrong answer.

Useful clauses: reduction(op:var), aligned(p:32), simdlen(8), private(t). Combine with threads: #pragma omp parallel for simd.

Alignment & Aliasing Hints

Aligned allocation

// C11: 32-byte aligned for AVX
float *a = aligned_alloc(32, n*sizeof(float));

#pragma omp simd aligned(a,b,c:32)
for (int i = 0; i < n; i++)
    c[i] = a[i] + b[i];

Aligned loads (movaps) can be faster than unaligned, and let the compiler skip a scalar "peel" prologue.

Tell the compiler pointers don't overlap

void axpy(int n, float s,
          float *restrict y,
          const float *restrict x) {
  for (int i = 0; i < n; i++)
      y[i] += s * x[i];   // no aliasing
}

restrict promises x and y name disjoint memory — removes the #1 reason auto-vectorization bails.

Module 4
Intrinsics — Hand-Written Vector Code

What Are Intrinsics?

Intrinsics are C functions that map (almost) one-to-one to SIMD machine instructions — assembly-level control with C syntax, register allocation handled for you.

Anatomy of a name

_mm256_add_ps
 │     │   │
 │     │   └ data type: ps = packed single
 │     └──── operation: add
 └────────── width: 256-bit (mm = 128, mm512 = 512)

Include <immintrin.h> for SSE/AVX intrinsics.

Vector typeHolds
__m1284 × float (SSE)
__m2568 × float (AVX)
__m256d4 × double
__m256ipacked integers
__m51216 × float (AVX-512)

A __m256 variable lives in a YMM register.

Load · Compute · Store

The core moves (256-bit, float)

#include <immintrin.h>

__m256 va = _mm256_load_ps(&a[i]);  // aligned load
__m256 vb = _mm256_loadu_ps(&b[i]); // unaligned load
__m256 vc = _mm256_add_ps(va, vb);  // 8 adds at once
_mm256_store_ps(&c[i], vc);         // aligned store

// broadcast a scalar to all 8 lanes
__m256 vs = _mm256_set1_ps(scale);
// fused multiply-add: vy = vs*vx + vy
vy = _mm256_fmadd_ps(vs, vx, vy);
load vs. loaduload_ps needs 32-byte alignment (faults otherwise); loadu_ps works on any address, historically a bit slower.
set1 / setzero_mm256_set1_ps(x) fills every lane with x; _mm256_setzero_ps() clears the register.

Worked Example — SAXPY by Hand

SAXPY: y = a*x + y over n floats.

Scalar baseline

void saxpy(int n, float a,
           const float *x, float *y) {
  for (int i = 0; i < n; i++)
      y[i] = a*x[i] + y[i];
}
PlanProcess 8 floats per step with AVX, then handle the leftover n % 8 with a scalar tail.
AVX intrinsics version

void saxpy_avx(int n, float a,
               const float *x, float *y) {
  __m256 va = _mm256_set1_ps(a);
  int i = 0;
  for (; i + 8 <= n; i += 8) {
    __m256 vx = _mm256_loadu_ps(&x[i]);
    __m256 vy = _mm256_loadu_ps(&y[i]);
    vy = _mm256_fmadd_ps(va, vx, vy);
    _mm256_storeu_ps(&y[i], vy);
  }
  for (; i < n; i++)            // scalar tail
      y[i] = a*x[i] + y[i];
}

The Remainder Tail (Loop Unrolling)

A vector step of k lanes handles ⌊n/k⌋ full chunks; the remaining n mod k elements need a scalar tail (or a masked step).

Why it mattersForgetting the tail is the classic SIMD bug: you silently skip the last n mod 8 elements, or read past the array end.
⌊26/8⌋ = 3 packed steps, 2 left over.
Module 5
Pitfalls — When Vectorization Fails

Loop-Carried Dependences

Cannot vectorizeIteration i reads a value written in iteration i-1 — lanes are not independent.

// recurrence — NOT vectorizable as-is
for (int i = 1; i < n; i++)
    a[i] = a[i-1] + b[i];

A packed add would compute all lanes from stale values of a[i-1].

Safe: reductionAccumulating into one scalar is a dependence, but a known, associative one — the compiler keeps a partial per lane and combines at the end.

#pragma omp simd reduction(+:s)
for (int i = 0; i < n; i++)
    s += a[i] * b[i];   // OK

Branches & Masking

SIMD has no per-lane branch. Conditionals become masks: compute both sides, then blend the lanes the predicate selects.


// scalar: data-dependent branch
for (int i = 0; i < n; i++)
    r[i] = (x[i] > 0) ? x[i] : 0;   // ReLU
Vectorized with a mask (AVX)

__m256 z  = _mm256_setzero_ps();
__m256 vx = _mm256_loadu_ps(&x[i]);
__m256 m  = _mm256_cmp_ps(vx, z, _CMP_GT_OS);
__m256 vr = _mm256_blendv_ps(z, vx, m);
_mm256_storeu_ps(&r[i], vr);

AVX-512 has true mask registers (k0–k7) for predicated ops and masked loads/stores — cleaner than blend.

Alignment, Aliasing & Strides

MisalignmentAligned load on an unaligned address faults (or forces slow peeling). Use aligned_alloc or loadu.
AliasingIf a, b, c might overlap, the compiler must assume the worst. Fix with restrict.
Non-unit strideGather/scatter (a[i*s], indirect a[idx[i]]) is far slower than contiguous loads — SoA beats AoS.
Also blocks vectorizationFunction calls in the body (unless inlined/vector-cloned), early break/exits, printf/I-O, and unknown trip counts. Keep inner loops small, flat, and contiguous.

Vector Programming — Big Picture

ModelSIMD = one instruction, many lanes — DLP inside a core.
HardwareSSE 128 → AVX 256 → AVX-512 512-bit registers; lanes = bits / 8·sizeof(T).
Get itAuto-vectorize → omp simd + align/restrict → intrinsics.
Intrinsicsload → _mm256_*_ps (use FMA) → store, plus a scalar tail.
Pitfallsloop-carried dependences, branches (mask them), misalignment, aliasing, strided access.
One sentence Write clean, contiguous, dependence-free inner loops; let the compiler vectorize them; verify with the report; reach for intrinsics only when the lanes refuse to fill.
