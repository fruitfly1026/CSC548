Module 1
Shared-Memory Processors & Threads

Uniprocessor vs. SMP

SMPSeveral CPUs, each with private cache, sharing one physical address space over a bus/interconnect.

Because memory is shared, threads communicate simply by reading and writing shared variables — no explicit messages. The catch is keeping those shared accesses correct (coherence) and fast (locality).

All CPUs share one address space.

Threads: the Unit of Parallelism

Why threads? Express parallelism within one process; map work onto the available cores; lightweight compared to processes.

Threads of a process sharethe same address space and resources (code, globals, heap, open files).
Each thread has its ownexecution state (ready/running/blocked), context (PC, SP, registers) and a per-thread stack.
Shared heap/globals; private stacks.

Portable Shared-Memory Programming

Thread librariesPOSIX threads (pthreads), Win32 API — explicit, low-level control.
Compiler directivesOpenMP — portable, incremental shared-memory parallelism. Our main focus.
AlsoMessage passing (MPI) for distributed memory; various parallel languages (few widely used).
Why directives win for SMP OpenMP standardizes ~30 years of SMP practice: add a few #pragma lines and the same source still compiles & runs sequentially without an OpenMP compiler.
Module 2
pthreads & Synchronization

The pthreads API

Core calls

pthread_create(&tid, NULL, start_fn, arg);
pthread_join(tid, &status);
pthread_exit(status);

pthread_mutex_lock(&lock);
pthread_mutex_unlock(&lock);

pthread_cond_wait(&cond, &lock);
pthread_cond_signal(&cond);

Return 0 on success; otherwise EINVAL, etc.

Hello, threads

#include <pthread.h>
void *new_thread(void *arg) {
  printf("hello, thread %d\n", *(int*)arg);
  return NULL;
}
int main() {
  pthread_t th;  int i = 1;
  pthread_create(&th, NULL, new_thread, &i);
  pthread_join(th, NULL);
}

Why Synchronization? — the Vocabulary

The problemThreads share globals & heap. Interleaved reads/writes to shared data give non-deterministic results.
Transfer $10 from A to B

A = A + 10;
B = B - 10;   // a "balance snapshot" between
              // these two lines is inconsistent
TermMeaning
Critical sectioncode that reads/writes shared data
Race conditioninterleaved critical sections → non-deterministic
Mutual exclusionensure exclusive execution of a critical section
Deadlockthreads permanently blocked, waiting on each other
Livelockexecution but no progress
Starvationa thread perpetually denied resources

Mutual Exclusion & Condition Variables

MutexOnly the lock holder modifies the protected data. Lock the whole transfer, not each variable, to keep it atomic.

Lock(transfer_lock);
A = A + 10;
B = B - 10;
Unlock(transfer_lock);
Condition variableWait for a condition without busy-waiting. Always paired with a lock.

wait(cv, lock) — atomically release lock & sleep; reacquire on wake.
signal(cv) — wake one waiter; broadcast(cv) — wake all.

Producer / Consumer (bounded buffer)

Producer

lock(&m);
while (count == max)      // buffer full
    cond_wait(&empty, &m);
put(item);
cond_signal(&full);
unlock(&m);
Consumer

lock(&m);
while (count == 0)        // buffer empty
    cond_wait(&full, &m);
int x = get();
cond_signal(&empty);
unlock(&m);
Use while, not if Re-check the condition after waking — another thread may have changed it (spurious wakeups, multiple consumers).
Module 3
OpenMP Basics — Fork-Join

Fork-Join Parallelism

ModelA master thread spawns a team at each parallel region, then the team joins back. Parallelism is added incrementally.

The sequential program evolves into a parallel one — one loop at a time. No OpenMP compiler? The pragmas are ignored and it runs serially.

Syntax & the Parallel Region

Pragma syntax (C/C++)

#pragma omp construct [clause [clause] ...]
#include <omp.h>

Applies to a structured block: one entry at the top, one exit at the bottom.

"Hello world"

#pragma omp parallel
{
  int id = omp_get_thread_num();
  printf("hello (%d) world\n", id);
}
Request threadsomp_set_num_threads(4) or env OMP_NUM_THREADS=4.

double A[1000];
omp_set_num_threads(4);
#pragma omp parallel
{
  int ID = omp_get_thread_num();
  pooh(ID, A);   // each thread runs this
}                // implicit barrier here

Each thread runs a copy of the block; A is a single shared array. All threads wait at the closing barrier.

The Five Categories of Constructs

Parallel regionsparallel — create the team.
Work-sharingfor, sections, single.
Data environmentprivate, shared, reduction…
Synchronizationcritical, barrier, atomic…
Runtime / envomp_*() calls & OMP_* variables.
Mental modelMost real OpenMP programs are: a parallel for + the right variable scoping + a reduction. Everything else is refinement.

Structured Blocks & the Software Stack

Constructs apply to a structured blockOne entry at the top, one exit at the bottom — no jumping in or out. (A hard exit() is the only allowed escape.)

#pragma omp parallel
{                        // one entry
  int id = omp_get_thread_num();
  res[id] = do_big_job(id);
}                        // one exit
// NOT structured: goto into / out of the region
Three layers cooperate
  • Directives (#pragma omp …) — what to parallelize
  • Runtime library (omp_*()) — query / control at run time
  • Environment variables (OMP_NUM_THREADS, OMP_SCHEDULE) — tune without recompiling

Lexical vs. Dynamic Extent

An orphan directive — outside the lexical text

// poo.c
void whoami() {
  int iam = omp_get_thread_num();
  #pragma omp critical          // orphan!
  printf("Hello from %d\n", iam);
}
// bar.c
#pragma omp parallel
{
  whoami();                     // called here
}
Lexical extentThe code textually inside the parallel braces.
Dynamic extentLexical extent plus any functions called from it at run time.
Orphan directiveA work-sharing / sync directive (e.g. critical) sitting in a function, firing only when reached inside a parallel region — lets you split parallel code across files.
Module 4
Work-Sharing Constructs

Splitting a Loop: omp for

By hand (SPMD)

#pragma omp parallel
{
  int id = omp_get_thread_num();
  int P  = omp_get_num_threads();
  int s = id*N/P, e = (id+1)*N/P;
  for (int i=s; i<e; i++)
    a[i] = a[i] + b[i];
}
With work-sharing

#pragma omp parallel
#pragma omp for
for (i=0; i<N; i++)
    a[i] = a[i] + b[i];
Implicit barrierat the end of omp for. Add nowait between two independent loops to remove it.

The schedule Clause

ScheduleHow iterations mapWhen to use
static[,chunk]deal out fixed blocks up frontpredictable, uniform work / iteration
dynamic[,chunk]threads grab chunks off a queueunpredictable, highly variable work
guided[,chunk]dynamic, blocks start large then shrinkcut scheduling overhead of dynamic
runtimeread from OMP_SCHEDULEdefer the choice to launch time
Trade-offStatic has near-zero overhead but can imbalance; dynamic balances load but adds queue contention. Tune chunk.

Sections & Combined Constructs

Function parallelism — sections

#pragma omp parallel
#pragma omp sections
{
  #pragma omp section
    x_calc();
  #pragma omp section
    y_calc();
}

Each section runs on one thread. Barrier at the end (or nowait).

Shortcut — combined

#pragma omp parallel for
for (i=0; i<MAX; i++)
    res[i] = huge(i);

Equivalent to parallel + for on separate lines. There is also parallel sections.

Module 5
Data Environment

Default Storage Attributes

shared — one copy, all threadsprivate — one copy per thread

Shared by default: globals, file-scope & static variables, heap.

Private by default: stack variables in functions called from the region; automatic variables in a block; the loop index of an omp for.


int A[10];               // shared
void work(int idx[]) {   // idx shared
  float temp[10];        // PRIVATE
  ...
}
#pragma omp parallel
{ work(index); }

Each thread gets its own temp; A and index are shared.

private / firstprivate / lastprivate

private(x)Fresh, uninitialized copy per thread; original undefined after the region.
firstprivate(x)Private, but initialized from the value before the region.
lastprivate(x)Copies the value from the last iteration out to the shared variable.

int IS = 0;
#pragma omp parallel for firstprivate(IS) lastprivate(IS)
for (j=0; j<1000; j++)
    IS += a[j];     // each thread starts IS at 0;
printf("%d", IS);   // IS = value at j==999 (defined, but not a real sum!)
Watch outThis is not how you sum an array — for that you need a reduction (next slide).

threadprivate & copyprivate

threadprivateGives each thread its own persistent copy of a global/static — preserved across parallel regions (lives on the heap).

Different from private, which masks the global and is re-allocated each region.

copyin vs copyprivatecopyin(A) broadcasts the master's threadprivate value to the whole team at a parallel region; copyprivate broadcasts a private value out of a single block to the other threads.

int A[N];
#pragma omp threadprivate(A)
init_data(N, A);
#pragma omp parallel copyin(A)
{ /* every thread sees initialized A */ }

Reduction

reduction(op:var)Each thread accumulates a private partial; partials are merged with op into the shared result at the join.

double sum = 0.0;
#pragma omp parallel for reduction(+:sum)
for (i=0; i<n; i++)
    sum += a[i];     // correct & ~2 lines added

FP cautionFloating-point + is not perfectly associative — results can differ in the last bits.

The default Clause

What's shared by defaultGlobals, file-scope & static vars are shared; locals in called routines and the loop index are private.
Override itdefault(shared) · default(none) · default(private) (Fortran only).
Reach for default(none)Forces you to declare the scope of every variable — the compiler errors on anything you forgot. The cheapest defense against accidental sharing & data races.

#pragma omp parallel for \
        default(none) shared(a,n) private(i)
for (i = 0; i < n; i++) a[i] *= 2;
Module 6
Synchronization Constructs

critical · atomic · barrier

critical

#pragma omp critical
  consume(B, res);

One thread at a time in the region.

atomic

#pragma omp atomic
  X = X + tmp;

Cheap critical for a single memory update.

barrier

#pragma omp barrier

All threads wait until everyone arrives.

ordered · single · master ordered forces sequential order in a block; single runs the block on one thread (barrier after); master runs on the master only (no barrier).

Implicit Barriers & False Sharing

Implicit barriers atend of parallel (mandatory — cannot be removed), and of for / sections / single — those three removable with nowait.

Use nowait to overlap independent phases — but only when the next phase truly doesn't depend on the previous.

False sharingPer-thread partials in sum[NUM_THREADS] land on the same cache line → threads ping-pong the line.

// BAD: false sharing
sum[id] += 4.0/(1.0+x*x);
// GOOD: private scalar + reduction

single · master · ordered

singleOne thread (any) runs the block; the others wait (implicit barrier). For one-time setup / I/O inside a parallel region.
masterOnly the master thread runs it; the others skip it — no barrier.
orderedInside an ordered loop, forces the block to run in iteration order — for deterministic output from a parallel loop.
single vs. masterBoth run a block once — but single synchronizes (barrier at end) while master does not. Pick by whether the other threads must wait.
Module 7
Tasks & Advanced Features

Task Parallelism (OpenMP 3.0+)

Why tasksFor irregular / recursive work (lists, trees) where loop counts aren't known up front.
Walk a linked list

#pragma omp parallel
#pragma omp single
{
  p = head;
  while (p) {
    #pragma omp task firstprivate(p)   // capture this node
      process(p);
    p = p->next;
  }
}   // barrier: tasks finish here
Recursive tree + taskwait

void postorder(node *p) {
  if (p->left)
    #pragma omp task
      postorder(p->left);
  if (p->right)
    #pragma omp task
      postorder(p->right);
  #pragma omp taskwait   // wait children
  process(p->data);
}

untied lets a suspended task resume on any thread when too many tasks pile up.

collapse · simd · runtime routines

collapse — fuse nested loops

#pragma omp parallel for collapse(2)
for (i=0; i<N; i++)      // parallel
  for (j=0; j<N; j++)    // parallel too
    a[i][j] = f(i,j);
simd — vectorize the inner loop

#pragma omp simd reduction(+:sum)
for (k=0; k<N; k++)
  sum += b[i][k]*c[k][j];

Loops must be properly nested with independent bodies. No correctness check by the compiler!

Module 8
Worked Example — Computing π

Computing π by Integration

Sequential — midpoint rule for π = ∫ 4/(1+x²) dx

long num_steps = 100000;
double step = 1.0/num_steps, x, sum = 0.0;

for (int i = 0; i < num_steps; i++) {
  x = (i + 0.5) * step;
  sum += 4.0 / (1.0 + x*x);
}
double pi = step * sum;
Parallel — add two clauses

#pragma omp parallel for \
        reduction(+:sum) private(x)
for (int i = 0; i < num_steps; i++) {
  x = (i + 0.5) * step;
  sum += 4.0 / (1.0 + x*x);
}
~2 linesreduction(+:sum) gives each thread a private partial, then sums them safely; private(x) keeps the scratch variable unshared.
Why it's correctNo lock, no shared-sum race — the reduction owns the combine step.

Three Routes to the Same π

1 · SPMD by handParallel region; each thread strides i = id, id+T, … into sum[id]. Works — but the partials share a cache line → false sharing.
2 · Work-sharingomp for splits the loop, but accumulating into sum[id] or a critical still costs contention / serialization.
3 · Reductionreduction(+:sum) — private partials, no false sharing, no lock. Fastest and simplest.
The lessonSame answer three ways; the right data scoping (a reduction) beats hand-rolled arrays and locks. Compare MPI's π (Topic 3): Bcast + Reduce — same shape, different model.

OpenMP — Big Picture

Createparallel forks a team (fork-join).
Dividefor / sections + schedule share the work.
Scopeprivate / shared / reduction.
Coordinatecritical, atomic, barrier, single — and mind implicit barriers.
Extendtask/taskwait, collapse, simd for irregular & vector parallelism.
One sentence Find the hot loop, scope every variable on purpose, use a reduction instead of a lock, and add the lightest synchronization that preserves correctness.
