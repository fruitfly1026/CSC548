Module 1
The Memory Hierarchy & Locality

The Memory Wall

Run time =cycles computing + cycles waiting for memory.

For decades CPU speed grew ~50%/yr while DRAM speed crawled. The gap — the memory wall — means a modern core can issue dozens of instructions in the time one DRAM access takes.

ConsequenceMemory access, not the floating-point unit, is the bottleneck. A cache is just a fast level in the hierarchy that hides this latency.
CPU vs. memory speed over time.

The Hierarchy — Speed vs. Size

Each level trades capacity for latency: smaller is faster, slower is cheaper. Data you reuse should live as high as possible.

LevelTypical latencySize
Registers~1 cycle100s of B
L1 cache~4 cyclestens of KB
L2 cache~10–15 cyc100s of KB
L3 cache~40 cycMBs (shared)
Main mem (DRAM)~200+ cycGBs
SSD / disk104–106 cycTBs
Higher = faster & smaller.

Locality — Why Caches Work

TemporalAn item used now is likely used again soon → keep it in cache and reuse it.
SpatialUsing an item makes its neighbors likely next → memory moves in cache lines, not single words.

Programs touch a small subset of memory in a regular way (the "90/10 rule": ~90% of time in ~10% of code). Hardware bets on locality; your job is to give it locality.

Spatial: row-major sweep is friendly

for (i = 0; i < N; i++)
  for (j = 0; j < N; j++)
    a[i][j] *= 2;   // contiguous in memory
Temporal: reuse x while it's hot

for (i = 0; i < N; i++)
  y[i] = x * w[i] + b;  // x reused every iter

A cache line is typically 64 bytes (32–128). One miss pulls in a whole line.

Module 2
Cache Basics — Just Enough

Lines & Associativity

Cache moves data in fixed lines (e.g., 64 B). Where can a memory line live in the cache?

Direct-mappedEach address has exactly one slot (addr mod size). Cheap, but two hot addresses mapping to the same slot evict each other.
N-way set-associativeEach set has N slots; the line may go in any of them. Fewer conflicts; a replacement policy (LRU / random) picks the victim.

Fully associative = "any slot" — flexible but costly; rare for large caches.

More ways → fewer conflict misses.

The 3 C's of Misses

CompulsoryFirst-ever touch of a line — "cold miss." Unavoidable; prefetching can hide it.
CapacityWorking set > cache size — lines get evicted before reuse. Fix by blocking/tiling.
ConflictToo many hot lines map to the same set, even though the cache isn't full. Fix by padding / more associativity.
Why a programmer cares You can't remove compulsory misses, but capacity and conflict misses are largely under your control — they're created (or avoided) by how you size, lay out, and traverse your data.

AMAT — Does a Miss Rate Matter?

Average Memory Access Time \( \text{AMAT} = t_{hit} + \text{(miss rate)} \times t_{penalty} \)

The miss penalty dominates: even a small miss rate hurts when the penalty is 100s of cycles.

LessonReducing the miss rate (via locality) pays off precisely because the miss penalty is so large.
Worked example

t_hit     = 1 cycle
miss_rate = 5% = 0.05
penalty   = 200 cycles

AMAT = 1 + 0.05 * 200
     = 1 + 10 = 11 cycles

A 5% miss rate turns a 1-cycle access into 11 cycles on average — an 11x slowdown driven entirely by misses.

Stalls, Out-of-Order & Prefetch

A miss stalls the pipelineOn a miss the core would sit idle for the whole penalty. Modern CPUs hide some of it with out-of-order execution — run other ready instructions from the reorder buffer (ROB) while the miss is outstanding.
Hardware prefetchStride detectors predict the next lines and fetch them before the load — turning would-be misses into hits for regular, sequential access.
Software prefetchIssue an explicit hint (__builtin_prefetch):
• Non-binding — load into cache; safe to mispredict.
• Binding — load into a register; must be the right address.
Why it matters to youPrefetchers love sequential, predictable access; they're defeated by pointer-chasing & random strides. Write loops the prefetcher can follow.
Module 3
Multicore: Coherence, False Sharing & NUMA

Cache Coherence (High Level)

Each core has private caches but they share one address space. Coherence hardware keeps everyone's view consistent — at the granularity of a cache line.

MESI, informallyEach line is Modified, Exclusive, Shared, or Invalid. A write must gain exclusive ownership, invalidating copies in other cores' caches.
The costCross-core invalidation traffic. Frequent writes to lines that other cores hold = an expensive coherence "ping-pong."
A's write invalidates B's copy.

Snooping & the MESI Protocol

Bus-based coherence: every cache snoops the shared bus and reacts to others' reads/writes. Each line carries one of four states:

StateMeaning
Modifiedonly copy, dirty (I own it)
Exclusiveonly copy, clean (matches memory)
Sharedclean copy; others may hold it too
Invalidstale — must refetch
A write needs ownershipTo write, a core must reach M — it broadcasts an invalidate, flipping every other copy to I.
The ping-pongTwo cores writing the same line trade ownership back and forth — each write is a bus transaction. This is the engine behind both true and false sharing costs.

At large scale the bus broadcast gives way to directory protocols (CC-NUMA).

False Sharing — the Silent Killer

WhatTwo threads write different variables that happen to sit on the same cache line. No logical sharing — but the line ping-pongs between cores anyway.
BAD: per-thread counters packed tight

long sum[NUM_THREADS];   // adjacent -> 1 line
#pragma omp parallel
{
  int id = omp_get_thread_num();
  for (i = id; i < N; i += NUM_THREADS)
    sum[id] += a[i];     // each write
}                        // invalidates others

8-byte longs: 8 of them fit in one 64-byte line, so all threads fight over it.

Logically private, physically shared.

Fixing False Sharing

Best fixDon't share the line at all — accumulate in a private scalar (or use a reduction) and write the shared result once.

double sum = 0.0;
#pragma omp parallel for reduction(+:sum)
for (i = 0; i < N; i++)
    sum += a[i];   // no shared line in hot loop
Alt: pad / alignForce each thread's datum onto its own line.

struct {
  long val;
  char pad[64 - sizeof(long)];  // fill line
} counter[NUM_THREADS];

// or: alignas(64), or _Alignas(64)

Padding wastes a little memory to buy back parallel scalability. Prefer the private/reduction fix when you can.

NUMA & the First-Touch Rule

On a multi-socket server, memory is NUMA — Non-Uniform Memory Access. Each socket owns local DRAM; reaching another socket's memory is slower.

First-touch policyLinux maps a page to the DRAM of the core that first writes it — not where it was malloc'd.
PitfallInitialize a big array serially and every page lands on one socket. Then all threads hammer that socket's memory remotely.
Parallel first-touch init

// touch with the SAME loop that
// will later compute -> pages land local
#pragma omp parallel for
for (i = 0; i < N; i++)
    a[i] = 0.0;        // first-touch here

#pragma omp parallel for
for (i = 0; i < N; i++)
    a[i] = f(i);       // now local access

Rule of thumb: initialize data with the same parallel pattern you'll use to process it.

Module 4
Programmer Takeaways

Loop Interchange — Stride Matters

BAD: column stride (jumps N words/iter)

for (j = 0; j < N; j++)
  for (i = 0; i < M; i++)
    x[i][j] = 2 * x[i][j];   // stride N
GOOD: row order = unit stride (C is row-major)

for (i = 0; i < M; i++)
  for (j = 0; j < N; j++)
    x[i][j] = 2 * x[i][j];   // stride 1
Same result, different trafficIn row-major C the inner loop should walk the last index. Swapping the loops turns a stride-N scatter into unit stride — one miss brings a line you then fully use.
Fortran is the oppositeColumn-major — the first index should be innermost.

Loop Fusion & Array Merging

Fusion — temporal localityMerge two passes over the same range so each element is reused while still hot, not reloaded in a second loop.

for (i = 0; i < N; i++) {
  a[i] = b[i] * c[i];
  d[i] = a[i] + c[i];   // a[i], c[i] hot
}
Merging — spatial localityInterleave arrays always used together so the values land on the same line.

// before              // after (one array)
int val[N], key[N];    struct{int val,key;} m[N];

The opposite layout (SoA) instead helps SIMD — choose by access pattern (next slides).

Blocking / Tiling for Locality

Naïve matmul — streams B repeatedly

for (i = 0; i < N; i++)
 for (j = 0; j < N; j++)
  for (k = 0; k < N; k++)
   C[i][j] += A[i][k]*B[k][j];

Re-reads all of B for each row of A → ~2N3+N2 traffic; little reuse once data > cache.

Tiled — operate on B×B subblocks

for (jj=0; jj<N; jj+=B)
 for (kk=0; kk<N; kk+=B)
  for (i=0; i<N; i++)
   for (j=jj; j<min(jj+B,N); j++)
    for (k=kk; k<min(kk+B,N); k++)
     C[i][j] += A[i][k]*B[k][j];

Capacity misses drop ~2N3 → ~N3/B. Pick B so the working blocks fit in cache (≈ 80–90% of capacity).

IdeaReuse a small block many times while it's hot, instead of sweeping whole rows/columns and evicting everything. This is what optimized BLAS (e.g., ATLAS) does for you — use the library when one exists.

Data Layout — AoS vs. SoA

Array of Structs (AoS)

struct P { float x, y, z; int id; };
struct P pts[N];

for (i=0;i<N;i++) pts[i].x += dx; // strided

Touching only x drags y,z,id into the line too → wasted bandwidth, poor for SIMD.

Struct of Arrays (SoA)

struct Pts {
  float x[N], y[N], z[N]; int id[N];
};
struct Pts pts;

for (i=0;i<N;i++) pts.x[i] += dx; // packed

All x values are contiguous → full line utilization, vectorizes cleanly.

RuleLay data out to match the access pattern. Sweep one field across all elements → SoA. Touch all fields of one element together → AoS. (Related: merging arrays into one struct improves spatial locality when fields are used together.)

Padding to Avoid Conflicts & Sharing

Conflict by power-of-twoEqual-sized arrays whose elements map to the same set evict each other every iteration.

#define DIM (1024*1024)
float a[DIM], b[DIM];
// a[i] & b[i] may collide in a
// direct-mapped / low-assoc cache
Fix: pad betweenOffset one array so the pair no longer aliases the same set.

float a[DIM];
char  pad[128];   // > one cache line
float b[DIM];

Same trick (padding to a line boundary) fixes both conflict misses and false sharing — it just separates things that shouldn't share a line.

Module 5
Case Study — Matrix Multiply & Tiling

Naïve Matmul: Memory-Bound


// C = C + A*B,  n x n
for (i = 0; i < n; i++)
  for (j = 0; j < n; j++)
    for (k = 0; k < n; k++)
      C[i][j] += A[i][k] * B[k][j];
B is read n timesThe inner k loop streams a whole column of B per (i,j) — and repeats it n times. Almost nothing stays in cache.
Count the slow accessesn³ (B columns) + n² (A rows) + 2n² (C) = n³+3n².
\( q = \dfrac{f}{m} = \dfrac{2n^3}{n^3+3n^2} \approx 2 \)
≈ 2 flops / wordTwo flops per slow word moved — memory-bound. The CPU can do far more flops than memory can feed.

Blocked (Tiled) Matmul


// b x b tiles that fit in cache
for (ii=0; ii<n; ii+=b)
 for (jj=0; jj<n; jj+=b)
  for (kk=0; kk<n; kk+=b)
   for (i=ii; i<ii+b; i++)
    for (j=jj; j<jj+b; j++)
     for (k=kk; k<kk+b; k++)
       C[i][j] += A[i][k]*B[k][j];
Reuse the tileLoad a b×b block of A, B, C once; do b³ flops before evicting. Reuse climbs from 2 to about b.
\( q \approx \dfrac{2n^3}{(2N+2)\,n^2} \approx b \)
Bigger tile → more reuseEfficiency grows with block size b — until the tiles stop fitting in cache.

How Big a Tile? The √(M/3) Limit

All three tiles must fitA, B, C blocks together in cache M:
\( 3b^2 \le M \;\Rightarrow\; b \le \sqrt{M/3},\; q \le \sqrt{M/3} \)
Hong & Kung (1981)No reordering using only associativity can beat q = O(√M). Tiling is asymptotically optimal for memory traffic.
Real libraries: multi-level tilingTile for L1, again for L2/L3, and register-block the innermost micro-kernel (the GotoBLAS / BLIS design). That's how BLAS reaches near-peak.

This is exactly the performance ladder you'll climb in the GEMM midterm.

Beyond Tiling: BLAS & Strassen

Use the libraryVendor BLAS (MKL, OpenBLAS, cuBLAS) already does multi-level tiling, packing & vectorization. Don't hand-roll GEMM for production — call dgemm.
Same trick everywhereTiling reappears as shared-memory tiling on the GPU (Topic 8) and SUMMA across nodes.
Strassen: fewer flopsA 2×2 multiply with 7 products instead of 8 → recursion gives O(n2.81) vs n³. Faster for large n, but more memory and worse stability.

The theoretical record exponent is ≈ 2.37 — not practical.

Big Picture — What a Programmer Must Know

Memory is the wallMisses cost 100s of cycles; AMAT is dominated by the penalty.
Give it localityTraverse contiguously (spatial); reuse while hot (temporal).
Tile big problemsBlock loop nests so the working set fits in cache.
Layout mattersAoS vs. SoA to match the access pattern; merge co-used fields.
Mind multicoreAvoid false sharing; respect NUMA first-touch.
Use the libraryTuned BLAS / ATLAS already does the hard tiling — reach for it first.
One sentence You rarely change the hardware — but choosing the right data layout, traversal order, tile size, and padding is how you keep the caches full and the cores from fighting each other.
