Distributed-memory programming with MPI
This is the distributed-memory half of the course. Each process has its own private address space; the only way to share data is to send explicit messages. We build up from the message-passing model and SPMD, learn the six core MPI calls, then point-to-point (blocking & nonblocking), collectives, communicators & derived datatypes, and finish with a real parallel-PI integration.

The Message-Passing Model & SPMD

By the end you can…

The Message-Passing Model

ProcessA program counter and a private address space. (A process may itself hold multiple threads sharing that one space.)

MPI coordinates communication among processes with separate address spaces. Interprocess communication is two things bundled together:

  • Synchronization — agreeing on timing
  • Data movement — copying bytes from one process's address space into another's
Nothing is shared — only messages cross.

Models of Parallel Computing

Data parallel (SIMD)Same instruction on many data items simultaneously.
Task parallel (MIMD)Different instructions on different data.
SPMDSingle Program, Multiple Data — every process runs the same program but branches on its rank. Not lock-stepped per operation.
Why SPMD SPMD is the practical way to write MPI: one source file, launched as p identical processes, each discovering "who am I?" via its rank and taking a different path. It is general enough to express MIMD behavior.

Cooperative Communication (Push Model)

In message passing, data is explicitly sent by one process and explicitly received by another — a cooperative exchange.

AdvantageAny change to the receiver's memory happens with the receiver's explicit participation. Communication and synchronization are combined.

One-sided Put/Get (MPI-2) decouples them — a "pull" model where only one side participates.

Sender pushes; receiver must cooperate.

What is MPI?

A specificationMPI is a message-passing library specification (an API) — not a language, compiler, or a single product.

Targets parallel computers, clusters, and heterogeneous networks. Full-featured, designed for end users, library writers, and tool developers. The guiding goal is portability.

A Minimal MPI Program

Hello, world (C)

#include "mpi.h"
#include <stdio.h>

int main(int argc, char *argv[]) {
  MPI_Init(&argc, &argv);
  printf("Hello, world!\n");
  MPI_Finalize();
  return 0;
}
  • mpi.h must be #included
  • Every MPI function returns an error code or MPI_SUCCESS
  • MPI_Init and MPI_Finalize bracket all MPI activity
Compile & run mpicc myprog.c -o myprog
mpirun -np 10 myprog  (or mpiexec -n 10)

Launch details are implementation-dependent (MPICH, OpenMPI, Intel MPI…).

Finding Out About the Environment

Every SPMD process asks two questions:

How many of us?MPI_Comm_size → number of processes.
Which one am I?MPI_Comm_rank → my rank, in 0 .. size-1.

MPI_COMM_WORLD is the default communicator holding all initial processes.

Better Hello (C)

#include "mpi.h"
#include <stdio.h>
int main(int argc, char *argv[]) {
  int rank, size;
  MPI_Init(&argc, &argv);
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);
  printf("I am %d of %d\n", rank, size);
  MPI_Finalize();
  return 0;
}

Module 1 — Review

1. What does it mean that MPI processes have "separate address spaces"?

No process can read or write another's memory directly. The only way to share data is to send a message that the other process explicitly receives.

2. In SPMD, how do two processes running the same program do different work?

They branch on their rank (from MPI_Comm_rank) — e.g. if (rank == 0) …. One program, multiple data, different control paths.

Point-to-Point Communication

By the end you can…

  • Use blocking MPI_Send/MPI_Recv with tags and MPI_Status

Basic Send / Receive — What to Specify

To fill in Send(data) / Recv(data) we must answer:

  • How is the data described? A triple (address, count, datatype).
  • How are processes identified? By rank within a communicator.
  • How does the receiver screen messages? By a user-defined tag.
  • What does "complete" mean? Depends on blocking vs. nonblocking.
Datatype tripleData in a message is (start, count, datatype). Labeling by type lets MPI bridge machines with different memory layouts (heterogeneous comm).
TagsAn integer that lets the receiver filter messages. Use MPI_ANY_TAG to accept any. (Tags avoid confusion with datatypes.)

Blocking Send & Receive

MPI_Send

MPI_Send(start, count, datatype,
         dest, tag, comm);
  • Buffer described by (start, count, datatype)
  • dest = rank of target in comm
  • On return, the data is delivered — buffer is reusable (but may not yet be received at the target)
MPI_Recv

MPI_Recv(start, count, datatype,
         source, tag, comm, &status);
  • Waits for a message matching source & tag
  • source may be MPI_ANY_SOURCE
  • Receiving fewer than count is OK; more is an error
MatchingA receive completes only when source and tag (and communicator) match a pending send.

The Status Object

When you receive with wildcards (MPI_ANY_SOURCE, MPI_ANY_TAG), the status structure tells you what actually arrived.

Fieldsstatus.MPI_SOURCE, status.MPI_TAG, and MPI_Get_count(&status, type, &n) for how many elements.
Reading status (C)

int recvd_tag, recvd_from, recvd_count;
MPI_Status status;

MPI_Recv(buf, n, MPI_INT,
         MPI_ANY_SOURCE, MPI_ANY_TAG,
         MPI_COMM_WORLD, &status);

recvd_tag  = status.MPI_TAG;
recvd_from = status.MPI_SOURCE;
MPI_Get_count(&status, MPI_INT, &recvd_count);

Sources of Deadlock

Unsafe patternBoth processes Send first. If there isn't enough system buffer space, each Send blocks waiting for the matching Recv that never starts → deadlock.

// Process 0        // Process 1
Send(1);            Send(0);
Recv(1);            Recv(0);

Called "unsafe" because it depends on the availability of system buffers.

Fix 1 — reorder

// Process 0        // Process 1
Send(1);            Recv(0);
Recv(1);            Send(0);
Fix 2 — nonblocking

// both processes
Isend(other);
Irecv(other);
Waitall();

Or use MPI_Sendrecv, which does both atomically.

Nonblocking Communication

MPI_Isend / MPI_Irecv return immediately with a request handle — the transfer is merely initiated. You must not touch the buffer until you confirm completion.

CompletionMPI_Wait(&req, &status) blocks until done; MPI_Test polls. Also MPI_Waitall / Waitany / Waitsome.
Overlap comm with compute

MPI_Request req;
MPI_Irecv(buf, n, MPI_INT, src, tag,
          MPI_COMM_WORLD, &req);

/* do useful work while the
   message is in flight ...    */
compute_something();

MPI_Wait(&req, MPI_STATUS_IGNORE);
/* now buf is safe to use */
Why nonblockingIt both avoids deadlock and lets you hide latency by overlapping communication with computation.

Communication Modes

Module 2 — Review

1. Why can two processes that both Send before they Recv deadlock?

If system buffers are too small, each blocking Send waits for the matching Recv to drain it — but neither process reaches its Recv. Reorder, or use nonblocking / Sendrecv.

2. After MPI_Irecv returns, when is it safe to read the buffer?

Only after a matching MPI_Wait (or a successful MPI_Test) reports the request complete — the receive merely started when Irecv returned.

Collective Operations

What Are Collectives?

DefinitionOperations called by all processes in a communicator. No tags. Blocking (MPI-1).
  • Barrier — synchronize the team
  • Broadcast — one-to-all
  • Scatter / Gather — distribute / collect pieces
  • Reduce / Allreduce — all-to-one (+ broadcast result)

In many numerical algorithms a send/recv pair can be replaced by a Bcast/Reduce — simpler and faster.

Broadcast & Scatter / Gather

APIMPI_Bcast(buf, count, type, root, comm) · MPI_Scatter / MPI_Gather (and the v / All variants for uneven sizes & all-receive).

Reduce & Allreduce

MPI_ReduceCombines a value from every process with an operator (e.g. MPI_SUM) and delivers the result to the root.

MPI_Reduce(&mypart, &total, 1,
           MPI_DOUBLE, MPI_SUM,
           0, MPI_COMM_WORLD);
MPI_AllreduceSame, but every process gets the result (Reduce + Bcast in one call).
opopop
MPI_SUMMPI_MAXMPI_MIN
MPI_PRODMPI_LANDMPI_LOR

Predefined ops are associative & commutative; user ops must be associative.

Module 3 — Review

1. How does a collective differ from point-to-point?

Every process in the communicator must call it; there are no tags; and it is blocking (in MPI-1). One call replaces a hand-written tree of sends/recvs.

2. When would you choose MPI_Allreduce over MPI_Reduce?

When all processes need the combined result (e.g. a global residual norm each rank must test) — it fuses the reduce and the broadcast into one efficient call.

Communicators, Groups & Contexts

CommunicatorA (group, context) pair. The group is an ordered set of processes; a process is identified by its rank in that group.

Every message lives in a context and must be received in the same context. MPI_COMM_WORLD is the default communicator with all initial processes.

Context vs. tagTags can collide between libraries and be defeated by wildcards. Contexts have no wildcards and are allocated by the system — so a library's messages never clash with yours.
Make a sub-communicator

MPI_Comm_split(MPI_COMM_WORLD,
               color, key, &newcomm);
// or: Comm_group / Group_incl
//     / Comm_create

MPI Datatypes

A message's data is a triple (address, count, datatype). A datatype is recursively defined:

  • predefined — MPI_INT, MPI_DOUBLE, …
  • a contiguous array of datatypes
  • a strided block (vector)
  • an indexed array of blocks
  • an arbitrary struct of datatypes
MPI typeC type
MPI_CHARsigned char
MPI_INTsigned int
MPI_LONGsigned long int
MPI_FLOATfloat
MPI_DOUBLEdouble
MPI_BYTE(raw bytes)

Why & How: Derived Datatypes

Why botherDescribe an application-oriented memory layout directly — e.g. a column of a row-major matrix, or an array of (int,float) pairs.
  • Avoids manual pack/unpack and extra memory-to-memory copies
  • Enables hardware scatter/gather when available
  • Supports heterogeneous communication across machine types
A strided vector type

MPI_Datatype col;
// count blocks, 1 element each,
// stride = N elements apart
MPI_Type_vector(N, 1, N,
                MPI_DOUBLE, &col);
MPI_Type_commit(&col);

MPI_Send(&A[0][j], 1, col,
         dest, 0, MPI_COMM_WORLD);
MPI_Type_free(&col);

Other builders: MPI_Type_contiguous, _indexed, _create_struct.

Module 4 — Review

1. Why are contexts safer than tags for library code?

A context is allocated by the system and admits no wildcards, so a library's messages cannot be accidentally matched (or hijacked) by application code using the same tag values.

2. What problem does a derived datatype solve?

It lets you send non-contiguous data (a matrix column, a struct) in one call, letting MPI handle the gather/scatter and avoid manual packing and extra copies.

Worked Example — Parallel PI

Computing PI by Integration

PI is the integral of \( \frac{4}{1+x^2} \) from 0 to 1. Approximate it with the midpoint rule over n intervals of width h = 1/n:

\( \pi \approx h \sum_{i=1}^{n} \frac{4}{1 + ((i-0.5)h)^2} \)

Parallel planProcess 0 reads n and broadcasts it. Each rank sums a strided slice of the intervals. A reduction adds the partials.

Parallel PI in C — the Full Program


#include "mpi.h"
#include <math.h>

int main(int argc, char *argv[]) {
  int n, myid, numprocs, i;
  double PI25 = 3.141592653589793238462643;
  double mypi, pi, h, sum, x;

  MPI_Init(&argc, &argv);
  MPI_Comm_size(MPI_COMM_WORLD, &numprocs);
  MPI_Comm_rank(MPI_COMM_WORLD, &myid);

  if (myid == 0) {
    printf("Enter # intervals: ");
    scanf("%d", &n);
  }
  MPI_Bcast(&n, 1, MPI_INT, 0,
            MPI_COMM_WORLD);


  h   = 1.0 / (double) n;
  sum = 0.0;
  for (i = myid+1; i <= n; i += numprocs) {
    x = h * ((double)i - 0.5);
    sum += 4.0 / (1.0 + x*x);
  }
  mypi = h * sum;

  MPI_Reduce(&mypi, &pi, 1, MPI_DOUBLE,
             MPI_SUM, 0, MPI_COMM_WORLD);

  if (myid == 0)
    printf("pi ~ %.16f, error %.16f\n",
           pi, fabs(pi - PI25));

  MPI_Finalize();
  return 0;
}

Dissecting the PI Example

1 · DistributeOnly rank 0 reads n; MPI_Bcast hands it to everyone — no per-rank send/recv.
2 · DecomposeThe loop i = myid+1; i <= n; i += numprocs gives each rank a strided (cyclic) slice — automatic load balance.
3 · CombineMPI_Reduce(MPI_SUM) adds every mypi into pi on rank 0.
The MPI pattern Almost every MPI program is this shape: broadcast inputs → compute on a local slice → reduce partial results. Master with point-to-point only when the structure is irregular.

MPI is Simple — the Core Six

Many parallel programs need only these six calls, only two of which are non-trivial:

MPI_Initstart up
MPI_Finalizeshut down
MPI_Comm_sizehow many?
MPI_Comm_rankwhich am I?
MPI_Sendsend a message
MPI_Recvreceive a message
Collective variantSwap Send/Recv for MPI_Bcast + MPI_Reduce and you can write the PI program — and many others — with no point-to-point at all.

Everything beyond the core six — modes, derived types, communicators, one-sided RMA, sessions — is refinement for performance, structure, or irregular communication.

MPI — Big Picture

ModelSeparate address spaces; cooperate by explicit messages. SPMD: one program, branch on rank.
Point-to-pointSend/Recv + tags & status; go nonblocking to dodge deadlock and hide latency.
CollectivesBcast, Scatter/Gather, Reduce/Allreduce, Barrier — all-process, no tags.
StructureCommunicators (group + context) isolate libraries; derived datatypes describe non-contiguous data.
Beyond MPI-1One-sided RMA (Put/Get), parallel I/O, dynamic processes, nonblocking collectives, sessions.
One sentence Decompose the data across ranks, broadcast the inputs, compute on each local slice, and reduce the partials — reaching for point-to-point only when the structure is irregular.
