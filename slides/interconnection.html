Part 1
The Interconnect Design Space

Nodes & Links

NodeEncapsulates one or more processors + memory hierarchy, a communication controller, and a router that connects it to other nodes.
LinkA set of wires interconnecting a pair of nodes. May be uni- or bidirectional.
Channellink + sender + receiver — the link plus the logic at each end.

Flits & Flow Control

FlitThe flow-control unit — the unit of transfer over a link. Flit size is set by link width, latency, and the amount of buffering.
Stop / go flow controlThe receiver sends a stop or go signal depending on available buffer space; the sender reacts by stopping or resuming flit transmission.

Switching Policies

Circuit switchingSet up a connection along the whole path before sending the message.

Pros: fast transmission, low per-packet overhead, energy efficient, no buffers needed, predictable latency.

Cons: high setup latency; low utilization when the reserved path is idle.

Packet switchingBreak the message into packets and route each one individually.

Pros: easy to maximize link utilization; no per-message setup.

Cons: needs larger buffers; higher and less predictable latency; higher per-packet overheads.

In practice Multiprocessor and on-chip networks overwhelmingly use packet switching — the small fixed messages and shared links make utilization matter more than setup latency.

Messages, Packets & Flits

  • A message is broken into packets (when one packet is insufficient)
  • Each packet has a header (routing info), payload (data), and trailer (error checking, etc.)
  • A packet is broken into flits; the packet is the unit of routing
  • Flits have no header: a head flit (first) carries routing info, followed by body flits

Network Topology = Shape of the Network

Topology determines the distance a message travels (in links / hops) from one node to another.

DiameterThe largest distance between any two nodes.
Average distanceMean hops over all source–destination pairs.
DegreeHow many links are connected to a switch.
Bisection bandwidth The minimum number of links cut when the network is partitioned into two equal halves — a measure of worst-case bandwidth between the two halves.

Simple Topologies

The building blocks, for p nodes: array, ring, mesh, tree. Short paths cost links or router ports. Torus, hypercube, fat tree and dragonfly (next slides) each fix one of these weaknesses.

Array and ring: cheap but slow2 ports per node, but distance grows with p, and everything crossing the middle shares 1 or 2 links.
Mesh: spread the load4 ports per node; distance grows with √p, and √p links cross the middle. The workhorse of on-chip networks.
Tree and star: short but centralizedPaths are short, but the root or hub carries all cross traffic: a single hot spot and a single point of failure.

Worked Example: A 2×3 Mesh

Compute diameter, average distance, and bisection bandwidth (as a multiple of link bandwidth L). All links bidirectional.

Popular Topology Families

k-ary d-dimensional mesh d = number of dimensions, k = nodes per dimension. A ring is 1-D; a 2-D mesh is the familiar grid.
HypercubeA binary d-dimensional mesh (k = 2). Degree grows with d.
k-ary tree & butterflyTree-structured and multistage networks — low diameter, but many switches.

Endpoints of the Space: Bus & Crossbar

Both give unit distance (diameter 1) between any pair of nodes. They bracket the cost and bandwidth extremes of the whole topology space.

BusOne shared medium reaching every node. Cost O(N), bandwidth O(1) shared by all, bisection width 1.
CrossbarEvery input can reach every output at once. Cost O(N²) switch points, bisection bandwidth O(N), degree N.
ScalabilityNeither scales: the bus saturates and the crossbar's O(N²) cost explodes. Crossbars survive inside VLSI, e.g. as the switch inside a single router.
Dally & Towles, Principles and Practices of Interconnection Networks; Culler, Singh & Gupta, Parallel Computer Architecture.

Torus: Mesh + Wraparound

Add a wraparound link at the end of every row and column of a mesh and you get a torus (a k-ary d-cube). A ring is the 1-D torus.

What the wrap buys
  • Diameter halves: \(d(k-1) \rightarrow d\lfloor k/2\rfloor\)
  • Bisection bandwidth doubles: \(k^{d-1} \rightarrow 2k^{d-1}\)
  • Every node looks the same: degree \(2d\) everywhere, no edge nodes
What it costs
  • \(dk^{d}\) links instead of \(dk^{d-1}(k-1)\); the wrap links are long unless the nodes are folded
  • The wrap creates a cycle in every dimension, so dimension-ordered routing alone is no longer deadlock-free (Part 2)
Dally & Towles, Principles and Practices of Interconnection Networks.

Fat Tree & Clos

A plain tree has bisection 1: all traffic between the halves squeezes through the root. A fat tree makes links fatter toward the root, so every level carries what the leaves can send.

Fat tree = folded ClosThree levels of identical k-port switches (edge, aggregation, core): \(k^3/4\) hosts, \(5k^2/4\) switches, at most 6 link hops between any two hosts, and full bisection bandwidth.
Why clusters use it, and what it costsUniform bandwidth between any two nodes, many equal-cost paths, commodity switches: the default topology of InfiniBand and Ethernet HPC clusters. The price is more switches and cables than a torus, and the long core-level cables cost the most.
Leiserson, "Fat-Trees" (1985); Al-Fares, Loukissas & Vahdat, SIGCOMM 2008.

Dragonfly

A hierarchical topology: a flattened butterfly with extra local hops so it needs fewer global hops, cutting the number of long, expensive cables.

StructureDense local groups joined by sparse global links. A group of a routers with h global links each connects all-to-all to up to \(ah\) other groups.
Degree\(k = p + a + h - 1\): p node channels per router, a routers per group, h global channels. Balanced design: \(a = 2p = 2h\).
Routing diameterMinimal = 3 hops (local, global, local). Valiant = 5: detour through a random intermediate group for load balancing.
Kim, Dally, Scott & Abts, "Technology-Driven, Highly-Scalable Dragonfly Topology," ISCA 2008.

Mesh: Increase k or Increase d?

When more nodes must be added, is it better to raise the arity (k) or the dimension (d)?

In favor of more dimensions
  • Diameter grows slower in hypercube & butterfly
  • Bisection bandwidth grows faster in hypercube & butterfly
The catch
  • Hypercube routers are more expensive (higher degree)
  • Butterfly needs a lot of routers
Reality on chip Low-dimensional meshes and tori dominate on-chip networks: wiring is planar, routers stay cheap, and (as we'll see) cut-through routing softens the diameter penalty.

Routing: Store-and-Forward vs. Cut-Through

Store-and-ForwardSend all flits over one link, then over the next, and so on.
\( T = H \cdot (T_r + L/B) \)
Cut-ThroughPipeline flits across links — a flit moves on as soon as the head is routed.
\( T = H \cdot T_r + L/B \)

H = distance (hops) · Tr = router delay · L = packet length · B = channel bandwidth.

Implication Cut-through makes latency depend mostly on L/B, not H — it reduces the importance of topology.

Aspects of a Routing Policy

Minimal?Minimal = every packet takes the fewest hops. Non-minimal may detour.
Deterministic?Deterministic = each src–dest pair always uses a single path.
Adaptive?Adaptive = a message can change path while in flight.
Deadlock-free? Deadlock arises when several messages mutually wait for each other's buffer space. A good policy is either provably deadlock-free or paired with an escape mechanism (Part 2).

Topology-Dependent Routing

In some topologies, the structure imposes the routing.

ButterflyRouting is minimal, deterministic, deadlock-free, non-adaptive. The destination ID directly selects the output port at each router along the path.
DownsideLack of path diversity reduces usable bandwidth under adversarial traffic patterns.

Routing in Mesh / Torus

Dimension-ordered (X-Y) Travel fully in X, then fully in Y, until the destination is reached. (Y-X is equally valid.) Simple, but lacks path diversity.
Valiant routing Pick a random intermediate node, route to it, then on to the destination. Non-minimal by design: it trades path length for path diversity, spreading adversarial traffic.

Up*/Down* Routing — Construction

A general scheme that enables routing in any topology, regular or irregular.

  1. Choose a root node.
  2. Breadth-first traversal: nodes reached become children; repeat until all are visited. Each child→parent link is an "up" link.
  3. For links within a level: the "up" direction goes from the higher-numbered node to the lower-numbered node (the lower ID is the "up" end).

Up*/Down* Routing — Valid Paths

RuleA valid path may go up first, then down, until the destination. Down-then-up is forbidden.
Why it worksForbidding the down→up turn breaks every cycle of channel dependence ⇒ deadlock-free.

Path diversity is provided, but the resulting paths may not be minimal.

Adaptive Routing

Adapts to the state of the network — avoids congestion by deflecting a packet to another port. May be minimal or non-minimal.

Risks
  • May meet worse congestion after deflecting
  • Livelock — a packet may circle forever; bound the number of deflections
Adaptive 1 — Source routing The routing table at the source encodes the full path; re-programmable for traffic / faults.

Pro: table looked up once at the source. Con: large table.

Adaptive 2 — Per-hop routing Each router's table holds only the next output port, not the whole path.

Pro: small tables. Con: a lookup at every router.

Part 2
Deadlock Avoidance & Router Architecture

What Is Deadlock?

The network's inability to forward packets, caused by limited buffer space and a cyclic dependence on buffer acquisition.

In the figure: four packets fill their input buffers and each needs the next output buffer — but that buffer is already full, in a cycle.

Handling deadlock:

  • Detect & break — expensive
  • Drop packets — hurts performance, complicates the protocol
  • Avoid — restrict routing
  • Adapt / escape — escape channel or separate VCs per packet type

Turn Restriction in Mesh Routing

Of the 8 possible turns in a 2-D mesh, forbidding the right subset breaks all cycles. Each scheme forbids a different pair.

Dimension-ordered (X-Y)Forbids all four turns from Y into X — you must finish X before turning into Y.
West-firstAll westward travel happens first; forbids the two turns into the west direction.
North-lastAll northward travel happens last; forbids the two turns out of the north direction.
Principle Cyclic channel acquisition is what enables deadlock — eliminating selected turns removes every cycle while still leaving many legal paths.

Example: Which Paths Are Allowed?

X-Y dimension-orderedAllowed: Path 4
West-firstAllowed: Paths 2, 3, 4
North-lastAllowed: Paths 1, 3, 4

Deadlock Avoidance & Escape

Avoidance (irregular)In up*/down* routing, forbidding the down→up turn avoids deadlock — the same cycle-breaking idea applied to any topology.
EscapeUse a virtual channel as an escape route from a possible deadlock. Routing within the escape channel must itself be deadlock-free.

Router Architecture

Router complexity depends on
  • Whether virtual channels are used
  • How many VCs share a physical channel
  • Whether wormhole or virtual cut-through is used

VCs add buffering and an allocation stage but enable escape channels and higher utilization.

The Router Pipeline

The head flit traverses four stages; body and tail flits inherit its route and only need switch traversal.

  1. DC — Decode & Compute: decode the header, compute the output channel, buffer at the input channel
  2. VA — Virtual-Channel Allocation: allocate an output VC for the packet
  3. SA — Switch Allocation: allocate the switch to connect input ↔ output VC
  4. ST — Switch Traversal: send the flit through the switch to the output VC
Non-speculative: VA then SA in sequence; if SA fails the flit stalls and retries SA. Speculative pipeline overlaps VA and SA into one stage to cut a cycle, gambling that the VC will be granted.

Case Study: Alpha 21364 Network

  • up to 128 nodes in a 2-D torus
  • Each node: Proc + 2 memory controllers + Mem + Router
  • Router ports: N, E, S, W + local cache + 2 MCs + 1 I/O (8 input ports, 7 output ports)
  • Minimal adaptive routing: one of two ports chosen by congestion, and the selected port must reduce Manhattan distance

Alpha 21364 — Flits, VCs & Deadlock

FlitsPhit = Flit = 39 bits (32 data + 7 ECC). The head flit holds the header (2-bit direction + 8-bit destination + 6 others).
Packet classesSeven classes (six non-special + one special) — requests = 3 flits, data / Write-IO responses = 18–19 flits. (Mukherjee et al., IEEE Micro 2002)
Virtual channels19 VCs per physical channel: three per non-special packet class (one adaptive, two deadlock-free: VC0 and VC1) plus one for the special class. Virtual cut-through is used, so VC buffer sizes differ by packet size.
DeadlockAdaptive routing isn't deadlock-free, so a blocked packet drains through VC0 / VC1, which route dimension-ordered. Which of the two a source–destination pair uses is computed offline (the simplest rule: VC0 if source ID < dest ID, else VC1).

Alpha 21364 — Router Pipeline

Pin-to-pin latency is 13 cycles (10.8 ns at 1.2 GHz): the router pipeline below plus 6 cycles of synchronization, pad and wire delay.

Scheduling pipeline (upper)
  • ECC — verify SECDED code (first), generate a new code (second)
  • DW — decode + write table entry
  • LA, GA — local arbitration (input port), global arbitration (output port)
  • RE — entry-table read
  • X — switch traversal
Data pipeline (lower)
  • WrQ, RQ — write to buffer / read from buffer
  • W — wait
TakeawayThe head flit drives scheduling; the data flits flow through the lower pipeline, decoupled from the routing decisions.
